# FitPilot Project Summary

> 项目状态：网页端饮食记录 MVP 持续开发中  
> 最后更新：2026-10-27

## 一句话介绍

FitPilot 是一个面向健身新手、大学生和日常健身用户的饮食管理应用。用户填写身体数据和健身目标后，系统自动计算每日热量与三大营养素目标，并通过网页完成食物记录、进度查看、体重趋势分析和饮食计划调整。

## 要解决的问题

刚开始健身的用户通常不知道自己每天应该吃多少，也很难把零散的食物记录转换成可执行的热量和营养目标。FitPilot 希望把这条流程连起来：

1. 根据身体数据生成可解释的营养目标；
2. 用更符合中国饮食习惯的食物库降低记录成本；
3. 将每日摄入、剩余目标和长期趋势集中展示；
4. 当用户从增肌切换到减脂时，让新计划及时生效，同时保留历史数据的正确含义。

## 当前产品闭环

```text
注册并填写身体信息
        ↓
计算 BMR、TDEE 和营养目标
        ↓
搜索内置食物 / 创建自定义食物 / 使用 AI 估算
        ↓
输入克数并记录到早餐、午餐、晚餐或加餐
        ↓
查看当日摄入、分餐小计、剩余目标和七日趋势
        ↓
记录体重或调整减脂、维持、轻盈增肌计划
```

## 已实现功能

### 账户与营养计划

- JWT 注册、登录和接口鉴权；后端根据登录身份访问用户数据。
- 后端常见请求和权限错误统一为 Problem Detail JSON，提供字段校验提示；拒绝非法日期、非正数食物/记录 ID 和整数的小数输入，保留 400/401/403 等明确状态。
- Redis 登录失败限流：按账号与来源组合计数，默认 15 分钟内失败 5 次进入冷却；支持多实例、429 重试倒计时及可信代理来源识别。
- 用户身体资料保存与修改。
- 营养设置只填写活动水平，注册及资料编辑无需重复填写每周训练次数。
- 使用 Mifflin–St Jeor 公式计算 BMR 和 TDEE。
- 根据减脂、维持、轻盈增肌目标计算每日热量、蛋白质、脂肪和碳水。
- 饮食目标按生效日期保存；调整计划不会篡改历史日期的目标。

### 饮食记录

- 85 个内置食物，覆盖常见原料和鱼香肉丝、宫保鸡丁、包子、饺子、油条、沙县鸡腿饭等中国常见食品。
- 食物搜索、营养预览和按克数换算。
- Redis 缓存内置食物搜索，最长保留 5 分钟，限制最多 128 条查询；自定义食物实时按用户隔离读取，编辑和归档立即生效；缓存故障自动回退数据库。
- Redis 搜索缓存故障后默认退避 5 秒，到期只允许一个请求探测恢复，其余请求继续查询数据库；内部记录缓存命中、故障、容量和回源耗时指标。
- 同一后端实例内，相同食物关键词的并发查询复用进行中的结果；最多保留 64 个主查询，跟随者最多等待 200 毫秒，超时自行回源，并记录合并/超时指标。
- 饮食记录新增、修改、删除和复制前一天记录。
- 可补记尚未建立营养目标的历史日期；显示实际摄入，不套用当前计划或虚构历史目标。
- 饮食记录保存录入时的食物名称和每 100g 营养快照；之后修改食物模板不会改变历史数据。
- 按早餐、午餐、晚餐、加餐分组，并显示每餐热量与三大营养素小计。
- 最近食物快捷入口会显示并自动带入上次克数与餐次，确认后即可再次记录。
- 用户自定义食物的创建、查询、修改和归档。
- 自定义食物按用户隔离，不会出现在其他用户的食物库中。
- 可选的大模型营养估算；用户确认或修正结果后再保存。已用真实 DeepSeek API 验证从网页估算、确认保存到刷新后查询的完整流程。

### 数据展示

- 今日 Dashboard：目标、已摄入和剩余热量及三大营养素。
- 七日摄入趋势、每日目标线、平均摄入与有效记录天数；点击趋势日期可查看当天明细或进入空白日期补记。
- 营养趋势使用 PostgreSQL 按天汇总，只返回日期范围内的每日统计；保留饮食快照及逐条舍入规则，避免加载完整食物、饮食实体。
- 体重记录与七日移动平均趋势；卡片内可选择历史日期补录和修改体重，缺少当日营养目标也可使用。
- 体重明细按日期倒序显示，支持直接编辑和确认后删除误录；删除后重算趋势与均值，记录按登录用户隔离。
- Swagger UI 可视化查看和测试后端 API。

### 训练模块现状

后端已经存在训练计划和训练记录的基础数据模型与接口，但当前产品开发有意优先完成饮食记录闭环。训练网页、双重渐进和训练建议暂不属于当前阶段。

## 技术架构

```text
React + TypeScript + Vite 网页端
              ↓ REST / JSON + JWT
Java 21 + Spring Boot 单体后端
 Controller → Service → Repository
              ↓ JPA
          PostgreSQL
```

- 后端：Java 21、Maven、Spring Boot 3.4.5、Spring Web、Validation、Spring Data JPA、Spring Security、Actuator、Flyway、springdoc-openapi。
- 前端：React、TypeScript、Vite。
- 数据库：PostgreSQL。
- 中间件：Redis，用于登录失败计数、并发预留与内置食物搜索缓存；业务数据继续存于 PostgreSQL。
- 架构选择：MVP 阶段使用结构清晰的单体应用，不提前引入微服务、消息队列或复杂 Agent 编排。

## 关键工程设计

- **登录身份作为数据边界**：受保护接口从 JWT 获取当前用户，避免客户端通过伪造 `userId` 访问别人的数据。
- **统一接口错误契约**：MVC 绑定、参数校验与安全过滤器均输出标准错误结构，客户端可按状态处理并展示 `detail` / `fieldErrors`；避免回显提交的敏感值，保留认证挑战、方法限制和限流相关响应头。
- **共享登录保护**：Redis Lua 原子处理失败计数、并发额度和过期；键使用账号/来源摘要，转发地址仅接受可信代理，Redis 故障时暂停登录而不影响已登录用户的数据操作。
- **有界共享缓存与故障回退**：内置食物查询采用 Redis Hash 缓存，Lua 原子约束容量与固定 TTL，空结果同样缓存；私有食物实时查询。缓存故障增加实例内退避和单请求恢复探测；同实例并发查询通过有界进行中请求表合并，跟随者等待超时后自行回源。Micrometer 固定标签指标记录命中、合并、故障和回源耗时，不公开监控 HTTP 端点。
- **营养目标保留历史版本**：目标带有 `effectiveDate`，Dashboard 按日期选择当时有效的目标。
- **无目标日期仍可记录事实**：历史 Dashboard 的目标与剩余量允许为空，实际摄入独立存在；趋势的目标与差值只比较有目标且有记录的日期。
- **饮食记录保存事实快照**：`food_logs` 同时保存录入时的食物名称和营养值；`foods` 可以继续作为可修改模板，历史 Dashboard 与趋势不会被回写。
- **数据库结构版本化与查询索引**：Flyway 按 V1–V4 管理建表与结构升级，Hibernate 只校验实体映射。新增按用户/日期/ID 的营养目标索引及按用户/食物/时间/ID 的记录索引，支持历史目标和最近食物查询；保留旧索引与营养快照。
- **真实数据库回归测试**：Testcontainers 在 Docker 临时 PostgreSQL 17 中从空库执行全部 Flyway 迁移，并验证表结构、约束与初始化数据，不依赖开发者本地数据库状态。
- **网页核心流程回归测试**：Vitest、Testing Library 和 jsdom 从登录界面驱动“登录 → 搜索并记录食物 → 切换减脂计划”，同时校验 REST 路径、请求体和 JWT 请求头。
- **真实浏览器端到端测试**：Playwright 使用桌面 Chromium、桌面 Firefox 和手机尺寸 Chromium 连接实际生产镜像与 PostgreSQL，覆盖注册、错误登录及“记录食物 → 调整计划”，并在结束后清理临时饮食记录。
- **开发与生产拓扑分离**：日常 Docker Compose 使用 PostgreSQL、Redis、Spring Boot 与 Nginx/React，方便独立开发；根目录生产镜像把 React 静态资源打入 Spring Boot JAR，一个非 root Java 容器同时提供网页和同源 `/api`。
- **基础设施即代码**：`render.yaml` 定义 Docker Web Service、私网 PostgreSQL 17 和 Redis Key Value，自动生成 JWT 密钥；production profile 禁止 Flyway 自动基线，新数据库必须执行完整版本迁移。
- **可观测部署健康**：Actuator 只公开 `/actuator/health`，Docker 和 Render 使用同一路径检查应用与数据库就绪状态，业务 API 的 JWT 边界保持不变。
- **按需持续集成**：较大更新后手动触发 GitHub Actions，先并行运行后端快速测试 / Testcontainers PostgreSQL、Redis 集成测试和前端 Vitest / TypeScript 检查 / 生产构建，再构建实际部署镜像并用 Playwright 验证桌面、移动端及跨浏览器真实链路；保留三类测试报告和失败诊断。普通小改动不跑测试，push 和 pull request 不自动触发。
- **精确表示营养数值**：重量和营养数据使用 `BigDecimal`，减少浮点误差。
- **内置与自定义食物共用模型**：内置食物的 `owner_id` 为空，自定义食物关联创建者，兼顾统一查询与用户隔离。
- **归档代替直接删除**：自定义食物使用 `active=false` 软删除，避免破坏已经存在的饮食记录。
- **复用最近一次录入习惯**：最近食物接口在多用户隔离与去重基础上返回上次克数、餐次和时间，网页自动填入但保留营养确认步骤，减少重复操作并避免误记。
- **事务保证批量操作一致性**：复制某日饮食、修改资料并重算目标等多步写入在事务内完成。
- **SQL 聚合与数值一致性**：跨日期营养趋势在 PostgreSQL 按用户/时间范围分组，使用历史快照及每条记录舍入后的营养值，只投影每日统计；保持与 Dashboard 的逐条算法一致，空白日和历史目标仍由服务层补齐。每餐小计等当前页面派生数据在前端计算。
- **图表同时承担日期导航**：七日趋势柱使用原生按钮语义、`aria-current` 和完整读屏说明，在桌面、手机与键盘操作中都能进入对应日期。

## 已知限制与技术债

- 默认配置为兼容开发早期数据库仍启用 Flyway `baseline-on-migrate`；production profile 已明确关闭自动基线。后续确认所有本地旧库都被 Flyway 接管后，可从默认配置移除兼容开关。
- 当前受 Spring Boot 管理的 Flyway 10.20.1 在 PostgreSQL 18.6 上运行成功，但会提示官方测试范围到 PostgreSQL 17，后续依赖升级需要再次验证。
- JWT 保存在浏览器本地存储中，尚未实现 refresh token、主动注销失效和更完善的生产安全策略。
- 内置食物搜索缓存最多延迟一个 TTL 反映食物库更新，可单独删除缓存 Hash 即时刷新；并发请求合并仅限同实例，跨实例、等待超时或容量溢出仍可能重复回源。已有内部缓存指标，尚未接入外部监控与性能压测，不宣称量化提速效果。
- CI 已覆盖后端、数据库迁移、前端测试 / 构建、生产镜像，以及 Chromium、Firefox 和手机视口真实链路；Render Blueprint 已就绪，但仍未接入自动部署或 WebKit。
- 浏览器自动化已覆盖注册、错误密码和核心饮食流程，但尚未覆盖接口超时/重试、WebKit、视觉回归和无障碍检查；也尚无线上监控和公开演示环境。
- AI 营养估算是可选辅助能力，结果受菜品做法和模型输出影响，不能视为权威营养数据。
- 拍照识别食物、移动端、HealthKit 和完整训练体验尚未实现。
- 无营养目标的历史日期可补记饮食和体重，只显示实际摄入，不计算达标比例。训练频率字段为兼容后端训练 API 保留，训练网页实现时需独立收集用户安排。

这个项目目前能够展示：

- 使用 Spring Boot 分层实现真实 REST API；
- 使用 JPA 和 PostgreSQL 进行关系建模、查询、约束与事务处理；
- 使用 Spring Security 和 JWT 实现登录与多用户数据隔离；
- 使用 React + TypeScript 完成从接口到可交互页面的产品闭环；
- 处理历史数据一致性、软删除、聚合趋势等超出基础 CRUD 的业务问题；
- 通过 GitHub Actions、分层自动化测试、Swagger 和持续文档维护提升项目的可验证性。
